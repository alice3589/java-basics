22. パッケージとimport

パッケージはクラスをまとめる「フォルダ（名前空間）」です。クラスが増えても整理でき、名前の衝突を防げます。Javaの標準ライブラリも java.util や java.time のようにパッケージで分かれています。

java.utilパッケージ
（フォルダ）
.→
ArrayListクラス
＝→
java.util.ArrayList完全修飾名

パッケージの宣言（ファイルの先頭）

自分でパッケージを作るときは、ファイルのいちばん上に package 文を書きます（フォルダ構成と一致させます）。

// ファイル: com/example/app/Hello.java
package com.example.app;   // このクラスが属するパッケージ

public class Hello {
    public void say() { System.out.println("こんにちは"); }
}

importで別パッケージのクラスを使う

別パッケージのクラスを使うときは import で取り込みます。java.lang（String・System・Math など）は例外的にimport不要で、いつでも使えます。

import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Integer> nums = new ArrayList<>();
        Collections.addAll(nums, 30, 10, 20);

        Collections.sort(nums);                     // 昇順に並べ替え
        System.out.println(nums);                   // [10, 20, 30]
        System.out.println(Collections.max(nums));  // 30

        // java.lang は import 不要（String, System, Math など）
        System.out.println(Math.max(5, 9));         // 9
    }
}
書き方意味
import java.util.List;Listクラスだけを取り込む（推奨）
import java.util.*;java.util直下の全クラスを取り込む
java.util.List（そのまま記述）importせず完全修飾名で書く
💡 同じパッケージのクラス同士はimport不要で使えます。パッケージは「com.会社名.アプリ名」のように、ドメインを逆にした名前が慣習です。

23. クラスの調べ方（API・Javadoc）

Javaには膨大な標準ライブラリがあり、必要な機能はたいてい誰かが用意してくれています。すべてを暗記する必要はありません。大切なのは「調べ方」を知ることです。その公式マニュアルが Javadoc（APIドキュメント） です。

Javadocの読み方

クラスのドキュメントには、次の情報が並んでいます。これを読めば、使い方が分かります。

🧱フィールド / コンストラクタ

そのクラスが持つデータと、生成方法（new の引数）。

🔧メソッド一覧

できることの一覧。名前・引数・戻り値の型が書かれている。

📥Parameters / Returns

各メソッドの引数の意味と、返ってくる値。

⚠️Throws

どんな例外が発生しうるか（try-catchの判断に使う）。

たとえば String のJavadocを開くと、repeat・strip・join といった便利なメソッドが見つかります。「こんな機能ないかな？」と思ったら、まずJavadocでそのクラスのMethod一覧を眺めてみましょう。

import java.time.LocalDate;

public class Main {
    public static void main(String[] args) {
        // String の Javadoc を調べると見つかるメソッドたち
        System.out.println("=".repeat(10));                   // ==========（Java 11+）
        System.out.println(String.join("-", "a", "b", "c"));  // a-b-c
        System.out.println("  trim me  ".strip());            // trim me（前後の空白を除去）

        // 日付を扱う java.time.LocalDate も Javadoc を読めば使える
        LocalDate d = LocalDate.of(2026, 6, 2);
        System.out.println(d.plusDays(30));                   // 2026-07-02
        System.out.println(d.getDayOfWeek());                 // TUESDAY（曜日）
    }
}
💡 公式Javadocは docs.oracle.com で公開されています。IDE（VS Code・IntelliJ）なら、メソッド名にカーソルを合わせるだけで同じ説明がポップアップ表示されます。
⚠️ メソッドの戻り値の型と引数の型を必ず確認しましょう。「このメソッドは何を返すのか」が分かれば、次に何ができるか（メソッドチェーン）も見えてきます。

24. ガベージコレクション

C言語などでは、確保したメモリを自分で解放する必要があり、忘れるとメモリリークの原因になりました。Javaには ガベージコレクション（GC） があり、もう使われなくなったオブジェクトを自動的に見つけて回収してくれます。だから free や delete を書く必要がありません。

new で生成ヒープに置かれる
→
参照が無くなる誰も指していない
GC→
自動で回収メモリが空く

「使われなくなった」とは？

どの変数からもたどれなくなったオブジェクトが回収の対象（GC対象）になります。下の例では、変数が新しい文字列を指した瞬間、元の文字列はどこからも参照されなくなります。

public class Main {
    public static void main(String[] args) {
        String msg = new String("古いデータ");
        System.out.println(msg);          // 古いデータ

        msg = "新しいデータ";              // 元のStringはどこからも参照されなくなる
        System.out.println(msg);          // 新しいデータ

        System.gc();                      // GCの「お願い」（実行タイミングはJVM任せ）
        System.out.println("不要になったオブジェクトはGCが自動的に回収します");
    }
}
  • System.gc() はあくまで「お願い」。いつ回収するかはJVMが決めるので、呼んでも即座に動くとは限りません（普段は書かなくてよい）。
  • 自動でもメモリリークは起こりえます。たとえばリストに入れたままremoveし忘れると、参照が残り続けて回収されません。
💡 プログラマは「メモリ解放」ではなく「不要になった参照を残さない（使い終わったらnullを入れる・コレクションから外す）」ことを意識すればOKです。

25. スレッド（マルチスレッド）

スレッドは「処理の流れ」です。ふつうのプログラムは main という1本の流れで動きますが、スレッドを使うと複数の処理を同時に進められます（ダウンロードしながら画面を動かす、など）。

mainスレッドstart()
→
スレッド1並行して実行
スレッド2並行して実行

Runnableで処理を渡して実行

Runnable（実行したい処理）を Thread に渡し、start() で動かします。join() を呼ぶと、そのスレッドが終わるまで待つことができます。

public class Main {
    public static void main(String[] args) throws InterruptedException {
        // Runnable をスレッドにして並行実行する
        Runnable task = () -> {
            long sum = 0;
            for (int i = 1; i <= 1000; i++) sum += i;
            System.out.println(Thread.currentThread().getName() + " の合計: " + sum);
        };

        Thread t1 = new Thread(task, "スレッド1");
        Thread t2 = new Thread(task, "スレッド2");
        t1.start();   // 別の流れで動き出す
        t2.start();
        t1.join();    // t1 の終了を待つ
        t2.join();    // t2 の終了を待つ
        System.out.println("両方のスレッドが終了しました");
    }
}
⚠️ start() と run() は違います。start() は新しいスレッドで実行、run() をそのまま呼ぶと今のスレッドでただのメソッド呼び出しになります（並行になりません）。
💡 上の例で最初の2行（各スレッドの合計）の表示順は実行ごとに変わることがあります。これがスレッドの特徴です。最後の行は join() で待っているので必ず最後に出ます。

26. 相互排除と同期

複数のスレッドが同じデータを同時に書き換えると、結果がおかしくなることがあります（競合状態／レースコンディション）。たとえば「読み取って＋1して書き戻す」の途中に別スレッドが割り込むと、せっかくの増加が打ち消されてしまいます。

⚠️ count++ は一見ひとつの操作ですが、内部では「読む→1足す→書く」の3ステップです。途中で別スレッドが割り込むと、数え落としが起きます。

synchronizedで一度に1スレッドだけ通す

相互排除（mutual exclusion）とは「同時に入れるのは1スレッドだけ」という制約のこと。synchronized を付けたメソッド（やブロック）は、ある瞬間に1つのスレッドしか実行できません。これで安全に共有データを更新できます。

public class Main {
    static int count = 0;
    static synchronized void increment() { count++; }  // 一度に1スレッドだけ

    public static void main(String[] args) throws InterruptedException {
        Runnable task = () -> { for (int i = 0; i < 100000; i++) increment(); };
        Thread t1 = new Thread(task);
        Thread t2 = new Thread(task);
        t1.start(); t2.start();
        t1.join();  t2.join();
        System.out.println(count);  // 200000（synchronized で正しく数えられる）
    }
}

もし synchronized を外すと、合計は 200000 より少ない不安定な値になりがちです（数え落とし）。付けることで、毎回ぴったり 200000 になります。

同期のための道具

道具用途
synchronizedメソッド／ブロックを排他制御（最も基本）
java.util.concurrent.atomic.AtomicIntegerカウンタなどを安全に増減（ロック不要で高速）
java.util.concurrent.locks.ReentrantLockより細かいロック制御
💡 「複数スレッドが同じ変数を書き換える」場面では必ず同期を考えます。逆に、各スレッドが別々のデータだけを触るなら同期は不要です。スレッド（25章）とセットで覚えましょう。
